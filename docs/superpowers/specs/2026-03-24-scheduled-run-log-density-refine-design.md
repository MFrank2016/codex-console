# 定时任务运行日志面板 D2 密度收紧设计文档

- 日期：2026-03-24
- 项目：codex-console
- 主题：定时任务运行日志面板二次密度优化（D2）

## 1. 背景

`/scheduled-tasks` 的运行日志弹窗已经完成过一轮 B3 风格改造：

- 弹窗整体宽度明显加大
- 时间展示统一为 `YYYY-MM-DD HH:mm:ss`
- 日志行拆成时间 / 级别 / 内容三列
- 复制仍保留原始日志文本

当前版本虽然已经比最初更紧凑，但用户进一步确认：

1. 还需要继续缩小日志行高
2. 还需要继续压缩行与行之间的垂直节奏
3. 希望达到 **D2** 级别的压缩效果：明显更紧，但不能压到 D3 那样过于拥挤

本次改造是在已上线的日志面板基础上做一次 **展示密度 refinement**，重点是继续收紧纵向节奏，而不是改动日志功能。

## 2. 已确认决策

- 视觉基线：保持当前 B3 宽屏日志弹窗
- 密度目标：采用 **D2**
- 优先策略：**CSS 微调为主**
- 日志逻辑：保持现有搜索、筛选、复制、自动滚动、自动换行不变
- 时间格式：继续保持 `YYYY-MM-DD HH:mm:ss`
- 复制语义：继续复制原始日志文本，不复制归一化显示文本
- 范围边界：只改运行日志弹窗，不改运行详情弹窗

## 3. 目标

1. 让运行日志弹窗一屏能容纳更多日志行
2. 继续降低每条日志的垂直占用，但不明显损伤可读性
3. 让状态栏、工具栏、控制台正文在视觉密度上更统一
4. 清理当前日志面板 CSS 中重复/互相覆盖的 spacing 定义，避免后续维护混乱
5. 保持现有前端行为和测试语义稳定

## 4. 非目标

- 不再继续扩大日志弹窗宽度
- 不修改后端日志格式与接口
- 不改变日志复制、搜索、级别筛选的语义
- 不把日志字体明显缩小一档
- 不把布局推进到 D3 的极限压缩状态
- 不调整计划列表、运行列表或运行详情弹窗布局

## 5. 当前问题

### 5.1 日志行仍偏高

当前 `.scheduled-run-console-shell` 已收紧过一轮，但单条日志的 line-height、行 gap 和内部 padding 仍偏保守，密度还没有到 D2。

### 5.2 badge 仍稍显厚重

级别 badge 已经具备固定列宽，但其垂直厚度仍偏明显，导致日志行视觉上仍有“鼓起来”的感觉。

### 5.3 状态栏 / 工具栏与正文密度不够统一

正文已经趋向紧凑，但状态栏和工具栏仍略显松，导致面板上部和日志区下部的节奏不一致。

### 5.4 CSS 出现重复 spacing 定义

当前 `static/css/style.css` 中：

- `.scheduled-run-console-status`
- `.scheduled-run-console-toolbar`

先定义了一组 padding / margin-bottom，后面又被共享规则覆盖。虽然界面结果正确，但可维护性较差。

## 6. 设计方案

采用“**只做 D2 级别 CSS 收紧 + 轻量测试补强**”方案：

- 不调整现有日志渲染结构
- 不调整现有 JS 行为
- 通过更细的 spacing、line-height 和 badge 厚度控制，继续压缩纵向空间
- 顺手清掉当前日志面板 CSS 中重复的 spacing 规则

### 6.1 日志正文 D2 收紧规则

日志区继续保持三列结构：

1. 时间列
2. 级别列
3. 消息列

但进一步压缩纵向空间：

- 控制台正文 `line-height` 从当前值继续下调到 **接近 1.24**
- 日志行 `gap` 再缩一档
- 日志行自身上下 padding 再缩一档

目标效果：

- 明显比当前版本更“薄”
- 一屏能多看到若干条日志
- 但仍然保持长时间阅读可接受

### 6.2 badge 厚度收紧

badge 的宽度策略保持不变，继续保证 `INFO / WARN / ERROR` 单行稳定展示，但其厚度进一步下降：

- 降低上下 padding
- 降低自身 line-height
- 保持圆角 pill 和现有语义色

结果应是：

- badge 看起来更像固定列
- 不会继续抢占太多垂直空间
- 不影响快速扫读级别

### 6.3 状态栏 / 工具栏同步压缩

为了避免“正文很紧、头部偏松”的割裂感，状态栏和工具栏同步进入 D2：

- padding 再缩一档
- margin-bottom 再缩一档
- 工具栏 group gap 再收一点

但保留：

- 多行换行能力
- 按钮可点击面积
- 当前控件布局和功能

### 6.4 控制台内边距收紧

控制台 shell 内边距再缩小一档，把更多空间让给日志内容本身。

这一步不改变：

- 宽度
- 边框
- 背景色
- 滚动行为

### 6.5 清理重复 spacing 定义

本次会把日志面板里重复/冲突的 spacing 定义收敛成单一来源，避免未来再出现：

- 上面定义一套值
- 下面再覆盖一套值

收敛原则：

- 对状态栏、工具栏保留一份最终有效的 spacing 规则
- 不改变其 class 结构
- 不扩大样式影响范围到其他 modal

## 7. 文件级设计

### 7.1 `static/css/style.css`

本次主改动文件。

改动目标：

- 继续压缩日志行 line-height、gap、padding
- 收紧 badge 厚度
- 收紧状态栏、工具栏和控制台内边距
- 清理重复 spacing 声明

### 7.2 `tests/test_scheduled_tasks_page_assets.py`

补强回归验证。

改动目标：

- 继续保证运行日志弹窗使用专属 class
- 补强“运行详情弹窗未被误伤”的断言
- 对本次 D2 样式关键点做轻量资源断言
- 保留并继续验证：
  - 秒级时间显示
  - 原始日志文本复制
  - 搜索 / 筛选 / 自动滚动相关行为

### 7.3 `static/js/scheduled_tasks.js`

原则上 **不需要改动**。

只有在测试或结构验证发现必须配合时，才允许做最小改动；默认本轮保持现状。

## 8. 测试策略

至少覆盖以下验证：

1. 运行日志弹窗专属 class 仍存在
2. 运行详情弹窗仍保持原本宽度规则，未被误伤
3. 样式表中日志面板 D2 相关选择器仍存在
4. 时间显示仍为秒级
5. 搜索 / 级别筛选 / 自动滚动相关测试继续通过
6. 复制日志仍复制当前可见的原始日志文本
7. 全部 scheduled task page asset tests 继续通过

## 9. 风险与控制

### 风险 1：压太紧导致可读性下降

控制：

- 不明显降低字体大小
- 只做 D2，而不是推进到 D3
- 保持时间列和级别列宽度不变

### 风险 2：样式调整误伤运行详情弹窗

控制：

- 继续只使用运行日志弹窗专属 class
- 增加“运行详情弹窗未被改宽/改形态”的回归断言

### 风险 3：样式规则越来越难维护

控制：

- 这次顺手清理重复 spacing 定义
- 把最终有效值收敛成单一来源

## 10. 验收标准

满足以下条件即可认为完成：

1. 运行日志弹窗比当前版本进一步紧凑，达到 D2 观感
2. 日志行垂直占用继续下降，但仍保持可读
3. badge 更薄，但仍能稳定单行展示级别
4. 状态栏、工具栏、正文的密度更统一
5. 运行详情弹窗未被误伤
6. scheduled task 相关 asset tests 继续通过
7. 搜索、筛选、复制、自动滚动、自动换行行为无回归
