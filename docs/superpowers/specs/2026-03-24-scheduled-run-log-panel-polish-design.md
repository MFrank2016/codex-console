# 定时任务运行日志面板宽屏紧凑化设计文档

- 日期：2026-03-24
- 项目：codex-console
- 主题：定时任务运行日志面板美化（B3 宽屏紧凑版）

## 1. 背景

`/scheduled-tasks` 的“运行记录”弹窗已经具备独立日志控制台、搜索、级别筛选、复制、清空、自动滚动和自动换行等能力，但当前视觉表现仍有 3 个明显问题：

1. 时间展示仍偏向原始日志格式，界面上不够统一，用户希望固定显示为 `YYYY-MM-DD HH:mm:ss`
2. 级别 badge 宽度偏窄，视觉上更像“临时标签”，不够稳定，也不利于一眼扫读
3. 日志弹窗宽度和行高仍偏保守，一屏能看到的有效日志条数不够多，长消息也容易换行

本次需求不再重做日志功能，而是在现有日志控制台基础上做一次纯展示层升级：采用用户确认的 **B 风格 + B3 宽度/密度方向**，把日志弹窗做成更宽、更紧凑、但仍保持控制台气质的版本。

## 2. 已确认决策

- 视觉方向：**B，保留深色控制台风格**
- 宽度方向：**B3，接近全屏展开**
- 密度方向：**进一步压缩行间距，提升单位视口信息量**
- 时间显示格式：**统一显示为 `YYYY-MM-DD HH:mm:ss`**
- 级别列要求：**加宽并保持单行展示**
- 改动策略：**采用轻量结构优化方案，不改后端日志存储和接口**

## 3. 目标

1. 运行记录弹窗在桌面端明显变宽，长日志更少换行
2. 时间列在界面中统一显示为秒级格式，不显示毫秒
3. `INFO / WARN / ERROR` 级别 badge 视觉上更稳定，单行展示不拥挤
4. 状态栏、工具栏、日志行整体更紧凑，一屏展示更多日志
5. 搜索、级别筛选、复制、自动滚动、自动换行、轮询加载等现有功能保持不变

## 4. 非目标

- 不修改 `scheduled_runs.logs` 的底层存储结构
- 不新增日志接口或结构化日志 API
- 不把日志控制台重做成完整数据表组件
- 不修改“运行详情”弹窗的布局宽度
- 不调整计划列表、运行列表、其他页面的日志/列表样式

## 5. 当前问题

### 5.1 日志弹窗横向空间不足

当前 `run-log-modal` 仍使用模板内联 `max-width: 960px`，在大屏上日志内容很快换行，不符合“看控制台、扫长消息”的使用场景。

### 5.2 时间格式偏原始日志而不是展示格式

前端日志解析目前优先识别毫秒级时间戳，渲染时直接输出原始 timestamp，导致界面时间格式和用户希望的“秒级统一展示”不一致。

### 5.3 级别 badge 视觉密度和稳定性不足

现有 badge 宽度较小，仍偏“点缀性标签”，在紧凑日志场景中不够像固定列；同时与时间列、正文列之间的节奏不够均衡。

### 5.4 单条日志垂直占用偏大

状态栏、工具栏、控制台内边距、日志行间距和 line-height 均偏保守，使得日志面板虽然可用，但信息密度不够高。

## 6. 设计方案

采用“**仅升级运行日志弹窗的结构承载与展示规则**”方案：模板中给日志弹窗增加语义化 class，CSS 中实现 B3 宽屏紧凑布局，JS 中把时间显示格式统一为秒级，同时保持日志原始文本、搜索、筛选和轮询逻辑不变。

### 6.1 弹窗宽度与外层承载

只调整“运行记录”弹窗，不影响“运行详情”弹窗。

具体策略：

- 为 `run-log-modal` 的 `.modal-content` 增加专用 class，例如：
  - `scheduled-run-log-modal-content`
- 不再依赖模板中的固定 `max-width: 960px` 作为最终视觉规则
- 桌面端日志弹窗目标宽度为：**接近 `92vw`，并设置合理上限**
- 设计基准可按以下数值落地：
  - `width: min(92vw, 1480px)`
  - `max-width: 1480px`

结果：

- 大屏时显著更宽，符合 B3
- 中等屏幕仍能在 `92vw` 内自适应
- 保留 modal 的全局遮罩、居中和最大高度规则

### 6.2 状态栏与工具栏紧凑化

保留现有状态栏与工具栏功能，但统一压缩垂直节奏：

- 状态栏 padding 从当前较宽的块状样式收紧为更紧凑的横条
- 工具栏上下外边距收紧
- 工具栏内部控件 gap 收紧
- 保留多行换行能力，避免窄屏时挤爆

设计原则：

- 功能按钮不减少
- 可点击目标尺寸仍保持可用
- 视觉重点从“控件堆叠”转移到“日志内容”

### 6.3 日志行排版规则

日志行统一为“三列结构”：

1. 时间列
2. 级别列
3. 消息列

建议落地为 grid：

- 时间列：固定宽度，保证完整显示 `2026-03-24 06:55:36`
- 级别列：固定宽度，作为视觉稳定的 badge 列
- 消息列：`minmax(0, 1fr)`，吞掉剩余空间

推荐列宽基准：

- 时间列：`160px`
- 级别列：`80px`
- 消息列：剩余空间

推荐日志行紧凑参数：

- 行 padding：`4px 8px`
- 行间 gap：`3px ~ 4px`
- 文本 line-height：`1.3 ~ 1.35`
- 控制台字体尺寸保持当前量级或略微下调，但不牺牲可读性

布局约束：

- badge 使用 `white-space: nowrap`
- 消息列允许在自动换行开启时正常折行
- 关闭自动换行时，整块控制台继续允许横向滚动

### 6.4 时间显示规则

日志原始文本继续保持后端返回值，不在前端 state 中改写；只调整“渲染时的显示格式”。

前端解析规则调整为同时支持：

- `YYYY-MM-DD HH:mm:ss.SSS`
- `YYYY-MM-DD HH:mm:ss`

推荐正则方向：

- 时间戳部分毫秒改为可选

显示规则：

- 如果时间戳带毫秒，渲染时去掉 `.SSS`
- 如果原本就是秒级，直接显示
- 如果整行不匹配统一日志格式，继续按普通文本行渲染

这保证：

- 新旧日志兼容
- 展示满足用户要求
- 复制、搜索、筛选仍可基于原始日志文本工作

### 6.5 级别 badge 规则

级别 badge 继续表达三种级别：

- `INFO`
- `WARN`
- `ERROR`

展示目标：

- 视觉上更像固定列而不是零散标签
- 宽度统一，单行展示稳定
- 各级别颜色区分明显，但不喧宾夺主

建议规则：

- 最小宽度提升到可稳定容纳纯文本 `INFO / WARN / ERROR`
- 保持圆角 pill 样式
- 使用更清晰的填充色而不是仅改文字色
- `ERROR` 行允许继续带轻微危险态背景，以增强定位效率

界面渲染层可直接显示 `INFO / WARN / ERROR` 文本；日志原始文本中的 `[INFO]` 格式不变。

### 6.6 控制台整体视觉

延续现有深色控制台基底，但做“更干净、更密集”的修饰：

- 控制台背景维持深蓝黑色系
- 行 hover 或危险态背景改成更细腻的透明色叠加
- 时间列颜色降低饱和度，作为辅助信息
- 消息正文保持最高阅读权重
- 控制台内边距收紧，优先把空间留给内容

最终效果应接近：

- 仍然像日志控制台
- 但更像“成熟后台产品中的日志中心”
- 不是普通 `<pre>` 文本块

### 6.7 响应式与窄屏行为

桌面端优先满足 B3 宽屏效果；窄屏下继续保证可用：

- 中小屏下弹窗宽度自动收敛到接近视口宽度
- 工具栏继续允许换行
- 当可用宽度不足时，日志三列布局可适度缩小 gap，但不改成完全堆叠布局
- 自动换行关闭时，仍由控制台自身提供横向滚动，不依赖页面整体滚动

## 7. 文件级设计

### 7.1 `templates/scheduled_tasks.html`

改动目标：

- 给运行记录弹窗的 `.modal-content` 增加专用 class
- 视需要给日志弹窗 body / console 区增加更明确的语义 class
- 尽量移除只服务于当前宽度的内联样式，把宽度规则回收到 CSS

不改动：

- 各个现有 DOM hook id
- 工具栏控件结构与按钮语义

### 7.2 `static/css/style.css`

改动目标：

- 新增运行日志弹窗的宽屏 modifier
- 紧凑化状态栏、工具栏、控制台内边距、日志行样式
- 固定时间列 / 级别列 / 消息列的布局规则
- 调整级别 badge 的宽度、颜色和单行展示策略
- 补充必要的响应式规则

### 7.3 `static/js/scheduled_tasks.js`

改动目标：

- 把日志解析正则改成“毫秒可选”
- 新增或调整时间显示格式化 helper，把显示值统一为秒级
- 在 `renderScheduledRunConsoleLine(...)` 中按新的三列结构输出更稳定的日志行 DOM

保持不变：

- 搜索逻辑（按回车应用）
- 级别筛选逻辑
- 自动滚动逻辑
- 清空视图逻辑
- 复制逻辑仍复制当前可见的原始日志文本
- 日志轮询与 stale request 防护逻辑

## 8. 测试策略

至少补充以下验证：

1. 模板测试：
   - 运行记录弹窗存在新的专用 class / hook
   - 现有日志控件 id 仍保留

2. 样式资源测试：
   - 样式表包含新的运行日志宽屏/紧凑化 class
   - 样式表包含新的时间列 / 级别 badge / 日志行布局规则

3. 日志解析与渲染测试：
   - 支持解析带毫秒的日志行
   - 支持解析不带毫秒的日志行
   - 渲染时统一输出秒级时间字符串
   - 非标准日志行仍按普通文本渲染

4. 行为回归测试：
   - 搜索仍只在回车时生效
   - 级别筛选仍只显示匹配行
   - 新日志 chunk 到达后仍会重新应用当前过滤条件
   - 自动滚动开启/关闭时滚动行为不回归
   - 复制仍复制当前可见日志文本

5. 结构展示测试：
   - 日志行输出中存在时间列、级别 badge、消息列
   - `INFO / WARN / ERROR` badge 在 HTML 结构中使用稳定 class

## 9. 风险与控制

### 风险 1：宽度放大后在中等屏幕上显得过满

控制：

- 使用 `min(92vw, 1480px)` 这类带上限的响应式宽度
- 保留 modal 外层 padding，避免贴边

### 风险 2：时间显示改为秒级后与复制文本不完全一致

控制：

- 明确这次是展示层格式化，原始日志文本不改
- 复制逻辑保持原始文本，避免影响排查和对外粘贴

### 风险 3：压缩行高后可读性下降

控制：

- 只压缩垂直节奏，不把字体压得过小
- 通过固定列宽和更稳定的 badge 样式弥补紧凑化带来的阅读压力

## 10. 验收标准

满足以下条件即可认为完成：

1. 运行记录弹窗在桌面端明显比当前更宽，达到 B3 方向
2. 日志时间统一显示为 `YYYY-MM-DD HH:mm:ss`
3. `INFO / WARN / ERROR` 级别列单行稳定展示，不再显得拥挤
4. 日志行、状态栏、工具栏整体更紧凑，一屏可见日志行数明显增加
5. 搜索、筛选、复制、自动滚动、自动换行、轮询刷新行为无回归
