# 定时任务运行详情 / 实时日志控制台设计文档

- 日期：2026-03-24
- 项目：codex-console
- 主题：定时任务运行详情与实时日志控制台改造

## 1. 背景

当前 `/scheduled-tasks` 的运行记录弹窗把“运行详情”和“实时日志”混在同一个视图里：

- 点击“详情”时也会看到日志区
- 点击“日志”时实际复用同一套详情视图
- 日志展示样式偏普通文本区，不够像专业日志控制台
- 日志内容缺少统一的毫秒级时间前缀，不利于排查问题

本次要把“详情”和“日志”彻底拆开，并把日志页升级成更专业的实时控制台。

## 2. 目标

1. 点击“详情”时，只展示运行详情，不显示日志
2. 点击“日志”时，展示独立的专业日志控制台
3. 实时日志每行带毫秒级时间信息
4. 日志控制台支持：
   - 自动滚动
   - 手动刷新
   - 复制日志
   - 清空视图（仅前端）
   - 自动换行开关
   - 关键词搜索
   - 级别筛选
   - 运行中任务的停止按钮
5. 新日志到达时，自动重新应用当前搜索和筛选条件

## 3. 非目标

- 不重做 `scheduled_runs.logs` 的底层存储结构
- 不把日志改造成独立日志表
- 不引入全文检索或服务端搜索 API
- 不改动计划列表和运行列表的基础信息结构

## 4. 设计决策

### 4.1 交互结构

采用 **方案 A：双入口 + 双弹窗**。

#### 运行详情弹窗

- 入口：点击运行列表中的“详情”
- 只展示运行元信息
- 不显示日志区
- 不触发日志流式轮询

字段包括：

- 计划名
- 任务类型
- 触发源
- 状态
- 开始时间
- 结束时间
- 持续时长
- 摘要
- 错误信息
- 停止请求信息

#### 日志控制台弹窗

- 入口：点击运行列表中的“日志”
- 独立于详情弹窗
- 顶部展示运行上下文状态条
- 下方展示控制台工具栏
- 主体展示深色 monospace 日志控制台
- 运行中时继续轮询日志增量

### 4.2 日志格式

后端继续存储文本日志，但统一新写入格式为：

`2026-03-24 21:15:02.123 [INFO] cleanup runner start`

支持级别：

- `INFO`
- `WARN`
- `ERROR`

旧日志兼容策略：

- 旧日志如果没有统一前缀，前端按普通文本行显示
- 不阻塞现有历史运行记录的查看

### 4.3 日志控制台 UI

#### 顶部状态条

展示：

- Run ID
- 计划名
- 当前状态
- 最后日志时间

#### 工具栏

展示：

- 刷新
- 自动滚动
- 复制日志
- 清空视图
- 自动换行
- 搜索框
- 级别筛选下拉框
- 停止运行

行为定义：

- 搜索：**按回车后**应用过滤
- 级别筛选：即时应用
- 清空视图：只清空前端当前显示缓存，不删除后端真实日志
- 自动换行：切换 `pre` 的 `white-space` 展示模式
- 复制日志：复制当前控制台可见内容

### 4.4 实时刷新与过滤策略

当日志控制台处于打开状态时：

- 如果运行仍在进行，前端继续按现有轮询机制拉取增量日志
- 每次拉到新日志后，自动重新应用当前：
  - 搜索关键字
  - 级别筛选
- 若开启自动滚动，则滚动到底部
- 若用户已关闭自动滚动，则保持当前位置

### 4.5 前端解析策略

前端以“行”为单位解析日志：

优先识别格式：

- 时间戳：`YYYY-MM-DD HH:mm:ss.SSS`
- 级别：`[INFO] / [WARN] / [ERROR]`
- 正文：剩余 message

解析成功时：

- 时间戳单独着色
- 级别按不同颜色展示
- 正文保持 monospace 文本

解析失败时：

- 按普通原始行渲染

### 4.6 后端改造边界

为了控制风险，本次不改日志存储模型，只在写入链路做统一封装：

- `append_run_log(...)` 增加统一时间格式化
- 增加可选日志级别参数，默认 `INFO`
- 关键告警/失败路径改写为 `WARN` / `ERROR`

调用侧调整原则：

- 正常进度、开始、完成：`INFO`
- 可恢复异常、跳过、候选缺失等：`WARN`
- 失败、异常终止：`ERROR`

## 5. 页面与代码结构影响

### 5.1 模板

`templates/scheduled_tasks.html`

- 新增独立“运行详情弹窗”
- 保留并重构“日志弹窗”
- 日志弹窗内增加控制台状态栏与工具栏挂载点

### 5.2 前端脚本

`static/js/scheduled_tasks.js`

需要拆分现有逻辑：

- `openScheduledRunDetail(...)`：只处理详情弹窗
- `openScheduledRunLog(...)`：只处理日志弹窗
- 增加日志行解析、过滤、重新渲染逻辑
- 增加复制、清空视图、自动换行、回车搜索逻辑

### 5.3 样式

`static/css/style.css`

新增/调整：

- 日志控制台深色面板
- 顶部状态条样式
- 工具栏布局样式
- 日志行、时间戳、级别颜色样式
- 换行/不换行展示差异

### 5.4 后端

可能涉及：

- `src/scheduler/run_logger.py`
- runner 中的日志写入调用点
- 如有必要，`/scheduled-runs/{run_id}/logs` 保持现有文本增量接口，不新增结构化返回

## 6. 测试要求

至少补充以下验证：

1. 页面模板存在独立详情弹窗和独立日志弹窗 hooks
2. 点击“详情”时渲染内容不包含日志面板
3. 点击“日志”时渲染专业控制台结构
4. 日志工具栏存在：
   - 复制
   - 清空视图
   - 自动换行
   - 搜索框
   - 级别筛选
5. 日志脚本包含回车搜索逻辑
6. 日志脚本包含按级别过滤逻辑
7. 新日志到达后会重新应用当前过滤条件
8. 运行日志写入格式带毫秒级时间前缀

## 7. 风险与控制

### 风险 1：旧日志与新格式混用

控制：

- 前端按“优先解析，失败则原样显示”处理

### 风险 2：前端过滤影响实时性能

控制：

- 仅在当前运行日志控制台内做本地过滤
- 保持文本增量接口，不做重型重算

### 风险 3：详情 / 日志逻辑耦合未拆干净

控制：

- 明确拆成两个弹窗与两套打开函数
- 测试覆盖“详情不显示日志”的核心要求

## 8. 验收标准

满足以下即视为完成：

1. 运行详情与日志彻底分离
2. 详情弹窗中不显示日志
3. 日志弹窗展示专业控制台样式
4. 日志每行带毫秒级时间信息
5. 支持回车搜索、级别筛选、复制、清空视图、自动换行、自动滚动
6. 新日志到达后自动重新应用当前过滤条件
7. 现有运行中心列表功能不回退
